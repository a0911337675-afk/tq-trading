# 2026/08/25 每日大事：OWASP 把 AI Agent 技能風險拉到檯面上

## 今天發生了什麼？

OWASP 的 Agentic Skills Top 10 專案近日被資安社群重新關注，官方頁面將「AI agent 技能」定義為讓代理系統真正能執行任務的執行層，並整理十大關鍵風險。這些風險包含惡意技能、供應鏈攻擊、權限過大、外部資源濫用、憑證外洩與審查不足等問題。

這則新聞值得放進「每日大事」，不是因為某家公司發布新產品，而是因為它指出 AI agent 的風險已經不只在模型回答是否正確。當 agent 可以讀檔、呼叫 API、執行腳本、連接資料庫或操作第三方服務時，真正需要管理的是整個工具與技能供應鏈。

## 用普通人的話來看

傳統聊天機器人多半只是回答問題；AI agent 則更像是會動手做事的自動化助理。它可以幫你整理資料、查詢系統、產生報表、下指令、改設定，甚至串接交易、雲端與內部營運工具。

問題在於，agent 之所以能做事，是因為它被賦予「技能」。技能通常包含設定檔、提示、腳本、API 權限與外部套件。如果其中一個技能被植入惡意指令，或引用了被污染的套件，agent 就可能在使用者不易察覺的情況下讀取敏感資料、洩漏金鑰、修改檔案或執行不該執行的操作。

對交易者與金融科技團隊來說，這和一般軟體供應鏈風險很像，但影響更難觀察。因為 agent 的行為常常是多步驟、半自主、依上下文變化；同一個技能在不同資料、不同權限與不同任務下，可能產生完全不同的風險。

## 為什麼值得注意？

第一，金融與交易自動化正在快速導入 AI agent。研究助理、客服流程、合規文件整理、資料管線監控、交易日誌分析與內部報表，都可能接上具備工具使用能力的模型。一旦技能層缺乏審查，風險就會從「回答錯誤」升級成「系統真的被操作錯」。

第二，技能供應鏈可能成為新的攻擊入口。過去團隊會檢查 npm、Python 套件與容器映像；未來也要檢查 agent 技能的來源、版本、權限、外部連線與更新流程。尤其是從公開市集、GitHub 或第三方範本下載技能時，不能只看功能描述是否好用。

第三，權限邊界會變得更重要。交易系統、金流後台、客戶資料庫與雲端帳號都不適合交給過度授權的 agent。即使模型本身沒有惡意，提示注入、資料污染或技能漏洞也可能讓 agent 誤用既有權限。

## 可以怎麼看？

對一般投資人來說，這則新聞提醒我們：AI 工具越能自動做事，越需要問清楚它能碰到哪些資料、能執行哪些動作，以及出錯時誰負責。不要只因為工具標榜「自動化」或「agent」就把帳號、金鑰與交易權限全部交出去。

對量化研究與金融科技團隊來說，可以把 OWASP 這份清單轉成幾個實務檢查：

1. 每個 agent 技能是否有明確來源、版本與審核紀錄？
2. 技能是否只拿到完成任務所需的最小權限？
3. 技能更新是否需要人工審查，而不是自動拉取最新版本？
4. agent 執行外部命令、讀取檔案或呼叫 API 時，是否有日誌與告警？
5. 高風險操作是否需要人類確認，例如下單、匯款、刪除資料或變更雲端權限？

AI agent 的價值在於把研究、資料處理與營運流程變快；但在金融場景裡，速度不是唯一目標。真正可靠的自動化，必須讓工具能力、資料權限與審計紀錄一起被設計，而不是等事故發生後才補。
